# Equivalence Verification Testbench

This testbench verifies that the **masked S-box** (1st-order Boolean masking) is functionally equivalent to the **original unmasked S-box**.

## Files

| File | Purpose |
|------|---------|
| `skinny_sbox_nor.c` | Original unmasked S-box implementation |
| `output.c` | Masked S-box (generated by DSE framework) |
| `equivalence_testbench.py` | Python script to generate and run C testbench |
| `equivalence_test.c` | Generated C testbench (auto-generated) |
| `equivalence_test` | Compiled executable (auto-generated) |

## How It Works

### 1st-Order Boolean Masking

In 1st-order Boolean masking, each bit is represented as two shares:
```
Original input:  x
Masked shares:   x = x0 ⊕ x1  (x0 and x1 are random, independent)

Original output: y = sbox(x)
Masked output:   y = y0 ⊕ y1  (computed securely from x0, x1)
```

### Verification Logic

The testbench verifies equivalence by:

1. **For each input** from 0 to 255:
   - Extract 8 bits: `in[0], in[1], ..., in[7]`

2. **Compute golden output** (unmasked):
   ```c
   sbox_golden(in[0], in[1], ..., in[7], &out[0], ..., &out[7])
   ```

3. **Compute masked output** (with share 1 = 0, randoms = 0):
   ```c
   sbox_masked(in[0], 0,    // i0_0, i0_1
               in[1], 0,    // i1_0, i1_1
               ...,
               &out_sh0[0], &out_sh1[0], ...)
   ```

4. **Verify equivalence**:
   ```c
   combined = out_sh0[i] ⊕ out_sh1[i]
   assert(combined == golden_output[i])
   ```

## Troubleshooting

### Issue: "Compilation failed"

**Solution**: Verify that:
- `skinny_sbox_nor.c` contains `void sbox(...)` function
- `output.c` contains `void sbox(...)` function and gadget definitions
- Both files are readable and have valid C syntax

### Issue: "All tests fail with garbage output"

**Solution**: Check:
- Are variables properly masked to 1-bit? (Use `& 1` operations)
- Are `_Bool` types properly converted to `int`?
- Are output pointers being dereferenced correctly?

### Issue: "Some tests fail intermittently"

**Solution**: 
- This suggests randomness or uninitialized variables
- Make sure all local variables in gadgets are initialized
- Verify that masked operations handle both shares correctly

## Mathematical Verification

For 1st-order Boolean masking to be secure:

1. **Correctness**: `y0 ⊕ y1 = sbox(x0 ⊕ x1)` ✓ (This testbench verifies)
2. **Security**: Probes of any single share reveal no information about `x`

This testbench only verifies **correctness**, not security!
